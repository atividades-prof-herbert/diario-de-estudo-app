# UC-02 — Manter matérias (CRUD)

**Produto:** Diário de Estudos  
**Objetivo:** permitir que o usuário crie, consulte, altere e exclua **matérias**.

## Atores

- **Usuário**
- **Sistema**

## Regras de negócio aplicadas

### RN-05 — Nome obrigatório
- `nome` da matéria é obrigatório.
- `nome` deve ter ao menos 1 caractere não em branco.

### RN-06 — Exclusão com dependências (tópicos e registros)


- Se a matéria possui **tópicos** e/ou **registros de estudo** associados, a exclusão deve ser **bloqueada**.
- O sistema deve orientar o usuário a remover primeiro os tópicos/registros (ou futuramente usar “arquivar”, se existir).

## Caso de uso: UC-02

### Pré-condições

- Nenhuma (para criar).
- Para editar/excluir: a matéria deve existir.

### Gatilhos

- Usuário aciona: **Adicionar Matéria**, **Editar Matéria**, **Excluir Matéria**, ou acessa **Lista de Matérias**.

---

## Subfluxo UC-02.1 — Criar matéria

### Fluxo principal (sucesso)

1. Usuário aciona **Adicionar Matéria**.
2. Sistema apresenta formulário (`nome`, `descricao` opcional).
3. Usuário preenche e confirma **Salvar**.
4. Sistema valida RN-05.
5. Sistema persiste a matéria.
6. Sistema retorna sucesso e exibe a matéria na lista.

### Fluxos alternativos / exceções

- **A1 — Nome inválido (vazio):** sistema rejeita e informa que o nome é obrigatório.

### Pós-condições

- Matéria criada e consultável.

---

## Subfluxo UC-02.2 — Listar matérias

### Fluxo principal (sucesso)

1. Usuário acessa a lista de matérias.
2. Sistema retorna matérias cadastradas (nome/descrição).

### Pós-condições

- Nenhuma alteração de estado.

---

## Subfluxo UC-02.3 — Editar matéria

### Fluxo principal (sucesso)

1. Usuário seleciona uma matéria existente e aciona **Editar**.
2. Sistema exibe valores atuais.
3. Usuário altera `nome` e/ou `descricao` e confirma **Salvar**.
4. Sistema valida RN-05.
5. Sistema persiste alterações.
6. Sistema retorna sucesso e atualiza a exibição.

### Fluxos alternativos / exceções

- **A1 — Nome inválido (vazio):** sistema rejeita e informa que o nome é obrigatório.
- **A2 — Matéria inexistente:** sistema informa que o registro não foi encontrado (ex.: já excluído).

### Pós-condições

- Matéria atualizada e consultável.

---

## Subfluxo UC-02.4 — Excluir matéria

### Fluxo principal (sucesso)

1. Usuário seleciona uma matéria e aciona **Excluir**.
2. Sistema solicita confirmação.
3. Usuário confirma.
4. Sistema verifica dependências (RN-06).
5. Sistema exclui a matéria.
6. Sistema retorna sucesso e remove da lista.

### Fluxos alternativos / exceções

- **A1 — Matéria com tópicos e/ou registros:** sistema bloqueia a exclusão e informa o motivo.
- **A2 — Matéria inexistente:** sistema informa que o registro não foi encontrado.

### Pós-condições

- Matéria removida (quando permitido).

## Cenários de validação

### CT-01 — Criar matéria com nome válido
**Quando** o usuário cria matéria com `nome="Matemática"`  
**Então** a matéria é persistida e aparece na listagem.

### CT-02 — Bloquear criação de matéria sem nome
**Quando** o usuário tenta criar matéria com `nome=""` (ou apenas espaços)  
**Então** o sistema rejeita e informa validação do nome.

### CT-03 — Editar matéria alterando nome
**Dado** uma matéria existente `M1`  
**Quando** o usuário altera `nome`  
**Então** o sistema salva e a listagem reflete o novo nome.

### CT-04 — Excluir matéria sem dependências
**Dado** uma matéria `M1` sem tópicos e sem registros  
**Quando** o usuário exclui `M1`  
**Então** `M1` deixa de existir e não aparece na listagem.

### CT-05 — Bloquear exclusão de matéria com tópicos/registros
**Dado** uma matéria `M1` com tópicos e/ou registros vinculados  
**Quando** o usuário tenta excluir `M1`  
**Então** o sistema bloqueia e informa o motivo.
