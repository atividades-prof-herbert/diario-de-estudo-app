# UC-05 — Consultar resumos/indicadores (matérias e tópicos)

**Produto:** Diário de Estudos  
**Objetivo:** permitir que o usuário visualize resumos no período (dia/semana/mês) por **matéria** e por **tópico**, com totais de tempo e desempenho em questões.

## Atores

- **Usuário**
- **Sistema**

## Regras de negócio aplicadas

### RN-13 — Agregações (totais)
- Para cada chave de agrupamento (matéria ou tópico), calcular:
  - `tempo_total_minutos` = soma de `duracao_minutos`
  - `questoes_feitas_total` = soma de `questoes_feitas`
  - `questoes_corretas_total` = soma de `questoes_corretas`

### RN-04 — Taxa de acerto
- Quando `questoes_feitas_total > 0`:  
  `taxa_acerto = questoes_corretas_total / questoes_feitas_total`
- Quando `questoes_feitas_total == 0`: taxa de acerto é **N/A**.

### RN-14 — Mesma lógica do histórico
- A seleção de período (dia/semana/mês) deve gerar os mesmos limites de intervalo usados no UC-04.

### RN-15 — Consistência com histórico
- Os totais exibidos no resumo devem ser compatíveis com a soma dos registros retornados pelo histórico no mesmo período.

> Observação importante (decisão de produto):
> - Este UC assume que **Resumo por Matéria** considera registros lançados diretamente na matéria **e** (se existirem) registros lançados em tópicos da matéria.
> - Se você preferir que o resumo por matéria considere apenas registros lançados diretamente na matéria, ajuste RN-13/RN-15.

## Caso de uso: UC-05

### Pré-condições

- Pode existir 0 ou mais registros de estudo.

### Gatilho

- Usuário acessa a tela/ação **Resumo**.

### Fluxo principal (sucesso)

1. Sistema apresenta opções de filtro por período (dia/semana/mês).
2. Usuário seleciona o período.
3. Sistema calcula/consulta agregações do período:
   - por matéria
   - por tópico
4. Sistema exibe, para cada matéria/tópico:
   - tempo total
   - total de questões feitas
   - total de acertos
   - taxa de acerto (ou N/A)

### Pós-condições

- Nenhuma alteração de estado.

## Fluxos alternativos / exceções

### A1 — Período sem registros
- Sistema exibe estado vazio ou lista vazia (ex.: “Sem dados para o período”).

### A2 — Dados inconsistentes
- Se o sistema encontrar registros inválidos na base (ex.: corretas > feitas), deve tratar como erro de dados (logar/alertar) e não produzir percentuais incorretos.

## Cenários de validação

### CT-01 — Resumo por matéria com questões
**Dado** no período existem registros de uma matéria `M1` com questões  
**Quando** o usuário consulta o resumo  
**Então** `M1` exibe totas corretos e taxa = corretas_total/feitas_total.

### CT-02 — Resumo por tópico com feitas=0
**Dado** no período existe um tópico `T1` com `questoes_feitas_total=0`  
**Quando** o usuário consulta o resumo  
**Então** a taxa de acerto de `T1` é **N/A**.

### CT-03 — Consistência com histórico
**Dado** o usuário consulta o histórico e obtém N registros no período  
**Quando** o usuário consulta o resumo do mesmo período  
**Então** a soma dos campos no resumo (tempo/feitas/corretas) equivale à soma dos N registros.

### CT-04 — Período sem registros
**Dado** não existem registros no período  
**Quando** o usuário consulta o resumo  
**Então** o sistema exibe estado vazio ou lista vazia.

### CT-05 — Agregar tópico dentro da matéria (assunção do UC)
**Dado** existe registro lançado em tópico `T1` pertencente à matéria `M1`  
**Quando** o usuário consulta o resumo por matéria  
**Então** os totais de `M1` incluem os dados desse registro.
