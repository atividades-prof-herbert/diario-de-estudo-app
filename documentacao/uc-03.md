# UC-03 — Manter tópicos (CRUD)

**Produto:** Diário de Estudos  
**Objetivo:** permitir que o usuário crie, consulte, altere e exclua **tópicos** vinculados a uma **matéria**.

## Atores

- **Usuário**
- **Sistema**

## Regras de negócio aplicadas

### RN-07 — Vínculo obrigatório com matéria
- Todo tópico deve estar vinculado a uma matéria existente (`materia_id`).

### RN-08 — Nome obrigatório
- `nome` do tópico é obrigatório.
- `nome` deve ter ao menos 1 caractere não em branco.

### RN-09 — Exclusão com dependências (registros de estudo)
- Se o tópico possui **registros de estudo** associados, a exclusão deve ser **bloqueada**.

## Caso de uso: UC-03

### Pré-condições

- Para criar/listar: deve existir uma matéria.
- Para editar/excluir: o tópico deve existir.

### Gatilhos

- Usuário aciona: **Adicionar Tópico**, **Editar Tópico**, **Excluir Tópico**, ou acessa **Lista de Tópicos** de uma matéria.

---

## Subfluxo UC-03.1 — Criar tópico

### Fluxo principal (sucesso)

1. Usuário acessa uma matéria existente.
2. Usuário aciona **Adicionar Tópico**.
3. Sistema apresenta formulário (`nome`, `descricao` opcional).
4. Usuário preenche e confirma **Salvar**.
5. Sistema valida RN-07 e RN-08.
6. Sistema persiste o tópico vinculado à matéria.
7. Sistema retorna sucesso e exibe o tópico na lista da matéria.

### Fluxos alternativos / exceções

- **A1 — Matéria inexistente:** sistema bloqueia e informa que a matéria não existe.
- **A2 — Nome inválido (vazio):** sistema rejeita e informa que o nome é obrigatório.

### Pós-condições

- Tópico criado e consultável na matéria.

---

## Subfluxo UC-03.2 — Listar tópicos por matéria

### Fluxo principal (sucesso)

1. Usuário acessa uma matéria.
2. Sistema lista tópicos vinculados àquela matéria.

### Pós-condições

- Nenhuma alteração de estado.

---

## Subfluxo UC-03.3 — Editar tópico

### Fluxo principal (sucesso)

1. Usuário seleciona um tópico e aciona **Editar**.
2. Sistema exibe valores atuais.
3. Usuário altera `nome` e/ou `descricao` e confirma **Salvar**.
4. Sistema valida RN-08.
5. Sistema persiste alterações.
6. Sistema retorna sucesso e atualiza a lista.

### Fluxos alternativos / exceções

- **A1 — Nome inválido (vazio):** sistema rejeita e informa que o nome é obrigatório.
- **A2 — Tópico inexistente:** sistema informa que o registro não foi encontrado.

### Pós-condições

- Tópico atualizado e consultável.

---

## Subfluxo UC-03.4 — Excluir tópico

### Fluxo principal (sucesso)

1. Usuário seleciona um tópico e aciona **Excluir**.
2. Sistema solicita confirmação.
3. Usuário confirma.
4. Sistema verifica dependências (RN-09).
5. Sistema exclui o tópico.
6. Sistema retorna sucesso e remove o tópico da lista.

### Fluxos alternativos / exceções

- **A1 — Tópico com registros de estudo:** sistema bloqueia a exclusão e informa o motivo.
- **A2 — Tópico inexistente:** sistema informa que o registro não foi encontrado.

### Pós-condições

- Tópico removido (quando permitido).

## Cenários de validação

### CT-01 — Criar tópico vinculado a matéria existente
**Dado** uma matéria existente `M1`  
**Quando** o usuário cria tópico com `materia_id=M1` e `nome="Funções"`  
**Então** o tópico é persistido e aparece na lista de tópicos de `M1`.

### CT-02 — Bloquear criação de tópico sem matéria
**Quando** o usuário tenta criar tópico sem `materia_id` (ou com matéria inexistente)  
**Então** o sistema rejeita e informa que a matéria é obrigatória.

### CT-03 — Bloquear criação/edição de tópico sem nome
**Quando** o usuário tenta salvar tópico com `nome=""` (ou apenas espaços)  
**Então** o sistema rejeita e informa validação do nome.

### CT-04 — Excluir tópico sem registros
**Dado** um tópico `T1` sem registros associados  
**Quando** o usuário exclui `T1`  
**Então** `T1` deixa de existir e não aparece na listagem.

### CT-05 — Bloquear exclusão de tópico com registros
**Dado** um tópico `T1` com registros vinculados  
**Quando** o usuário tenta excluir `T1`  
**Então** o sistema bloqueia e informa o motivo.
